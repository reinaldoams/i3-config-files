Yabridge on Fedora 44
i3 Spin

A practical guide based on a real installation session. Documents what worked, what didn't, and known limitations.

Fedora 44 i3wm Reaper VST3 Audio working GUI working Mouse workaround needed
What is yabridge? Yabridge lets you use Windows VST2, VST3, and CLAP plugins in Linux DAWs (like Reaper, Ardour, Bitwig) by bridging them through Wine. The plugin appears to your DAW as a native Linux plugin.

STEP 01

Install Wine Staging from WineHQ

Always required — yabridge needs a recent Wine Staging build

Fedora's default Wine from dnf install wine works for installation but has a known mouse click regression. Use WineHQ's build instead.

⚠
On Fedora 44, the --add-repo flag doesn't exist. Use addrepo (without the dashes) instead.

Add the WineHQ repository

bash 
sudo rpm --import https://dl.winehq.org/wine-builds/winehq.key

sudo dnf config-manager addrepo \
  --from-repofile=https://dl.winehq.org/wine-builds/fedora/$(rpm -E %fedora)/winehq.repo

sudo dnf install winehq-staging

Verify

bash 
wine --version
# Should show: wine-X.X (Staging)
STEP 02

Install yabridge (prebuilt binary)

Always required
⚠
The patrickl/yabridge COPR does not support Fedora 44 as of June 2025. The prebuilt binary from GitHub is the only reliable method.
bash 
cd /tmp
wget https://github.com/robbert-vdh/yabridge/releases/download/5.1.0/yabridge-5.1.0.tar.gz
mkdir -p ~/.local/share
tar -xzf /tmp/yabridge-5.1.0.tar.gz -C ~/.local/share

Add yabridgectl to PATH

bash 
echo 'export PATH="$PATH:$HOME/.local/share/yabridge"' >> ~/.bashrc
source ~/.bashrc

Verify

bash 
yabridgectl --version
# Should show: yabridgectl 5.1.0
STEP 03

Install Windows Plugins via Wine

Only if you have Windows-only VST plugins
bash 
wine /path/to/PluginInstaller.exe

Plugins typically install to one of these Wine prefix paths:

paths 
# VST3
~/.wine/drive_c/Program Files/Common Files/VST3/

# VST2
~/.wine/drive_c/Program Files/VSTPlugins/

# Vendor-specific example
~/.wine/drive_c/Program Files/Neural DSP/
STEP 04

Add Plugin Directories to yabridgectl

Every time you add a new plugin directory
bash 
yabridgectl add ~/.vst
yabridgectl add "$HOME/.wine/drive_c/Program Files/Common Files/VST3"
yabridgectl add "$HOME/.wine/drive_c/Program Files/Neural DSP"
✗
Always quote paths with spaces. Use $HOME or quotes — do not use backslash-escaped spaces, as they cause "directory not found" errors.

Check registered directories

bash 
yabridgectl status
STEP 05

Sync Plugins

After adding directories, after installing new plugins, after updating yabridge

This creates the Linux bridge .so files next to your Windows DLLs. Your DAW will scan these and see the plugins as native Linux plugins.

bash 
yabridgectl sync
STEP 06

Configure Reaper to Find Plugins

First time only, or after adding new plugin directories
✓
In this setup, Reaper found the plugins automatically after yabridgectl sync without any manual configuration.

If Reaper doesn't find them automatically, add the directories manually via:

Options → Preferences → Plug-ins → VST

STEP 07

Install DXVK

If the plugin GUI is black, not updating when moved, or visually glitching

DXVK was needed in this setup to fix the UI redraw bug.

bash 
sudo dnf install wine-dxvk
wineboot --init
yabridgectl sync
ℹ
The Fedora 44 wine-dxvk package integrates automatically — no setup script needed. The DLLs are placed directly into the Wine system directory.
STEP 08

i3: Make Plugin Windows Float

Required on i3 and other tiling window managers

Without this, plugin windows get tiled, which interferes with input handling.

Add to ~/.config/i3/config

i3 config 
for_window [class="wine"] floating enable
for_window [class="Wine"] floating enable

Reload i3

keybind 
$mod + Shift + r
STEP 09

yabridge.toml Configuration

If mouse clicks don't register inside the plugin GUI

Create ~/.config/yabridge/yabridge.toml

toml 
[defaults]
editor-force-dnd = true
editor-xembed = false
hide-daw = false

[compatibility]
editor-coordinate-hack = true
input-event-filter = false
bash 
yabridgectl sync
⚠
All keys must use hyphens (editor-force-dnd), not underscores (editor_force_dnd). Mixed syntax is silently ignored.

Known Issues & Limitations

Mouse clicks only work at top-left corner
Root cause

A regression introduced in Wine 9.22 that breaks mouse coordinate mapping for embedded plugin windows. All Wine versions from 9.22 onward (including 10.x and 11.x) are affected.

Proper fix

Wine built with the "vulkan childwindow patch" (wine-tkg). The patrickl/wine-tkg COPR provides this for Fedora, but only up to Fedora 43.

Current workaround

Keep the plugin window positioned at the top-left corner of the screen. Mouse clicks work correctly there due to coordinate offset behavior.

Attempted fix — Kron4ek wine-tkg 9.21
bash 
cd /opt
sudo wget https://github.com/Kron4ek/Wine-Builds/releases/download/9.21/wine-9.21-staging-tkg-amd64.tar.xz
sudo tar -xJf wine-9.21-staging-tkg-amd64.tar.xz
sudo mv wine-9.21-staging-tkg-amd64 wine-tkg-9.21
yabridgectl set --wine-home /opt/wine-tkg-9.21/bin
yabridgectl sync
✗
Binary extracted correctly, but yabridge continued using system Wine 11.0. The set --wine-home command did not persist. Needs further investigation.
Track upstream
github.com/robbert-vdh/yabridge/issues/382
copr.fedorainfracloud.org/coprs/patrickl/wine-tkg/
Child/dropdown windows open behind the plugin window
Root cause

Same Wine childwindow regression as above.

Workaround

When a dropdown or child window opens behind the plugin, move the front window aside, interact with the child window, then move the front window back to top-left to continue.

patrickl/yabridge COPR not available for Fedora 44

The COPR only has builds up to Fedora 43. Using the prebuilt binary from GitHub releases (Step 2) is the correct workaround.

patrickl/wine-tkg COPR not available for Fedora 44

Only Fedora 42 and 43 are supported. Manually adding the fc43 repo and forcing the install fails — the sub-packages (wine-core, wine-cms, etc.) are not built for fc43 in that COPR, causing unresolvable dependencies.

WineHQ repo syntax difference on Fedora 44

The standard dnf config-manager --add-repo flag does not exist. Use addrepo --from-repofile= instead (see Step 1).
